The method

Find one defect, prove its scope, gate the class

Every gate on that rail exists because a person or an agent looked at a door and saw something obviously wrong that no automated check caught. The loop that works: find one defect, measure how many of the thousand doors share it, fix the generator, add a deterministic gate so the class cannot return, regenerate and confirm.

Two independent finders drive it. A second physics engine — Isaac Sim and PhysX checked against MuJoCo — catches anything where two engines disagree about what the model means. A visual review renders each door as a twelve-panel sheet captioned with what the spec claims is there, and asks an agent what looks wrong; it found defects in 97 of 122 doors, every one of which passed all gates. Neither replaces the other, and both produce false positives that must be killed by measurement rather than argument.

What nobody has picked up

  • Closer mechanisms as real linkages. The closing torque is applied at the door hinge, and the arm linkage is kinematic decoration the viewer solves. The real mechanism puts the spring and hydraulic valves on the pinion and lets the torque curve emerge from the linkage's changing mechanical advantage. Largest remaining physics gap; brief in handoffs/closer-mechanisms.md.
  • Run the visual review over all 1000 doors. Only 122 were reviewed, by an agent. The tool is built and mock-tested but has never run live — it needs an API key. About $50 for one request per door, $25 through the batch API. Unfixed findings are listed in docs/review/vision/triage.md.
  • Moving-versus-moving clearance. The clearance gate only measures moving parts against static geometry. Two leaves of a pair, adjacent fold panels, a leaf against a moving mullion are unguarded. The machinery already exists; seals and astragals that legitimately compress need a documented budget.
  • Taxonomy hierarchy page and the browser physics playground. Both requested, never started; partial work sits on two older branches.
  • Sign-off has no mandatory-checklist rule, so a door passes with whichever checks happened to run. A required-checks manifest per family would close that.
Hard-won

Operational notes that save hours

  • Work in a git worktree, never the main checkout. Another agent works in the repo root directly and switches branches; commits made there land wherever it happens to be pointing.
  • Never commit assets/ from a branch. It is generated, it is seven thousand files, and it conflicts in every merge. Avoid git commit -a and git add -A, which sweep it in. Regenerate after every merge — several times a branch landed new geometry against stale committed assets and the suite went red for unrelated reasons.
  • When a process looks slow at 0% GPU and 100% CPU, get a stack before theorising. faulthandler.dump_traceback_later found an Isaac Lab callback looping render() forever in headless mode after hours of wrong guesses. py-spy cannot ptrace inside the container.
  • Half of a visual review's first findings will be the renderer, not the doors. Reflective materials mirroring the skybox, black doors rendering as silhouettes, invisible clear glazing, a camera fitted to the bounding sphere so the close-ups were not close. Fix the camera before believing the finding.
  • Agents should commit and push early and often. Two entire batches of parallel agents were killed by usage limits mid-flight; the ones that had committed lost nothing.
