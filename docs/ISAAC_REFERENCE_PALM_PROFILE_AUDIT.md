# Reference-tail accounting for the optional palm-load schedule

The detached `admit_standing_reference_tail` admission preserves the original
exact source/active-target equality when no profile is declared. For the
explicit `release-unload-restore-v1` profile, it instead checks the captured
active request against an independent reconstruction of the fixed schedule.
It does not modify the captured values or invoke a live controller.

The original outer runtime path/hash and its copied document must already
match the actual observation provenance. The optional accounting additionally
binds its source configuration hash, the exact saved duration/start, the
unchanged source6 N target, captured support implementation, and original
operation report. It reads the full bounded JSON withdrawal stream, requiring
every contiguous500 Hz post-step epoch and the first actual release event at
its recorded command epoch. The event cannot be moved, erased or changed.
Every active target, source/maximum target, schedule phase and fixed ramp epoch
must match the independent scalar formula. The final three tail samples must
match that stream and retain their actual source/active values.

For source42.548 s and duration8 s, with release44.218 s, the final submitted
command at50.546 s requests5.999999720839327 N. Its immutable source and hybrid
maximum remain6 N. The mathematical schedule reaches6 N at50.548 s; the prior
command must not be relabeled or rounded to that terminal value. The captured
post-step state at50.548 s remains distinct from the command at50.546 s.

The result adds `support_profile_accounting` only for an explicit profile,
including the three verified active targets and bound event epochs. Original
motion, contact, source and motor predicates are unchanged. Missing profile
history, unknown/null profile, changed input hash, missing/truncated stream,
wrong epoch, altered source target or mismatched active request rejects
admission. A failed physical episode can still have truthful observation
accounting; this result grants zero stages and does not qualify its physical
source, promise minimum contact force, or limit leaf speed.

CPU tests use synthetic source histories and the existing real observation
decoder. They include the actual prospective42.548/44.218/50.548 clock values,
all schedule phases, default equality, distinct source/active targets,
event/duration/provenance corruption, and unchanged captured-tail values.
